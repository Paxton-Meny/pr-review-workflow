# Code of conduct

This project exists to make code review rigorous and humane at the same
time, and the same bar applies to the people in it. The rules below
cover every space the project runs: issues, pull requests, review
threads, discussions, and commit messages.

## The standard

Argue about code, evidence, and design. Never about people.

- Critique work on its merits. "This loop re-reads the file on every
  iteration" is a finding; "you clearly didn't think about this" is
  not, and the first one is more useful anyway.
- Disagree with evidence. A benchmark, a failing case, or a line
  reference settles more than volume does. It is fine to be wrong in
  public here; it is how most of this project got built.
- Assume competence. People arrive with different backgrounds, tools,
  and first languages. Terse is fine, condescending is not.
- Keep it on topic. This is a workspace, not a venue for politics,
  advocacy unrelated to the project, or commentary on anyone's
  identity, employer, or personal life.

The following get no warning and no debate: harassment, personal
attacks, slurs, sexualized language or attention, doxxing or
publishing anyone's private information, and sustained disruption
after being asked to stop. The same applies to content smuggled in
through commits, branch names, or generated output.

## Reviews in particular

Because this repository ships a review tool, review culture is on
display. Findings name defects, never authors. A rejected suggestion
deserves a reason. Nobody is required to accept a change they can
refute, and nobody gets to relitigate a settled thread by exhaustion.

## Enforcement

One maintainer runs this project, so enforcement is simple and honest
rather than ceremonial: the maintainer reads reports, decides, and
acts. Measures run from a correction in the thread, to removal of the
content, to temporary or permanent exclusion from the project's
spaces, depending on severity and history. Egregious cases skip the
intermediate steps.

To report something, use GitHub's built-in reporting on the content
itself, or open an issue if the matter is not sensitive. For anything
you would rather raise privately, contact the maintainer through
their GitHub profile. Reports are read, and reporters are not
punished for reporting in good faith.

Maintainer conduct is held to this document too. If the maintainer is
the problem, say so in the report; it will still be read.
